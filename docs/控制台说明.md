# 本地控制台说明（v1.1）

## 启动

首次双击 setup.bat，之后双击 start.bat。浏览器自动打开本机页面，不需要部署任何服务器。需要关闭工具时先等待任务结束，再关闭启动时的命令窗口；仅关闭浏览器不会停止后台任务。

默认地址是 http://127.0.0.1:8765。如果端口已被占用，自动使用 8766～8775 中首个可用端口，浏览器和页脚会显示实际地址。这台电脑的 8765 被百度输入法占用，实际验证使用 8766，未停止或更改该程序。

同一工程只允许运行一个控制台实例。重复双击会打开原有实例。不同浏览器标签页共享同一单任务锁，运行期间不能换市场或修改凭证/设置。

## 日常操作

- 当前市场下拉框读取 markets.json，自动写入原 runtime.json。店铺 ID 只显示，不开放随意修改。
- ArkSwift 登录窗口接受 Cookie 或 Authorization_web，存回原 sku_write/auth.json；不读取回显现有内容。测试连接只读当前店铺 status 接口。
- CL 窗口接受完整 GetDetail cURL，存回原 revflow/getdetail.curl.txt。仅接受现有 cl.aosom.cloud 的 HTTPS GetDetail 请求；测试复用 RevFlow 的请求与返回 SKU 校验。
- 顶部“已配置”只表示文件存在/有内容；不能代替连接测试。CL 测试也不能独立确认来源国家，切市场时需更新对应国家的请求。

### Step 1

粘贴 SKU 或选择/拖入 TXT/CSV，UTF-8、无表头、每行一个。点击开始检测会自动保存原始输入、调用 Python Detect，并生成原有格式的三份清单与完整性记录。

Python Detect 复用 ArkSwiftClient 的登录会话、市场 storeId，沿用原 JS 的正常商品过滤、分页、精确匹配、三次重试。请求失败始终为 ERROR，不会被算作 Existing。每十项保存一次，未完成项保留 ERROR。

“重试 Errors”从已验证的完整结果重建队列，只重查失败 SKU，合并保留成功/已存在结果。缺少完整结果时重新检测原清单。

浏览器 Console 的旧 sku_detect.js 保留，可作为备用入口，但日常无需再复制脚本。

### Step 2

点击开始抓取，直接运行原 revflow/revflow.py。输入仍是完整清单 + Need Create 掩码，已有 SKU 保留为 SKIP_EXISTS；不会仅传 Need Create 而丢失完整审计范围。

进度和 CLI 日志自动显示。结束后可预览 Summary/错误或打开目录。抓取失败需处理后重跑，保持原续跑行为。

### Step 3

运行原 preflight.py。旧预检报告可以显示，但未有本控制台的当前批次校验记录时，需要重新预检才会解锁 Step 4。

Mapping 有问题时点击“打开 / 填写建议 CSV”，首次自动从原 review 复制为 suggested 文件并用默认程序打开。填写 suggested_target/confidence/review_note 后保存；也可将 AI 返回的 CSV 通过页面导入。建议文件仍是原格式，不增加另一套映射系统。

Apply Mapping 调用原 apply_mapping_review.py，继续执行实时 taxonomy 合法性检查与原备份逻辑；成功后自动调用 preflight.py。任何 BLOCKED / CL_ERROR 或剩余 Mapping 问题均不允许创建草稿。

Mapping 数量显示问题条数，BLOCKED 是 SKU 数，可能包含同一 SKU 的 Mapping 问题，不是互斥总数。

### Step 4

Dry Run 调用原 main.py --dry-run，通过后才可点击创建草稿。弹窗显示当前市场、店铺和按原 CLI 选择/续跑规则计算的待创建数量。

确认后调用原 main.py。Payload、图片上传、草稿保存、150035、resume、State/Audit 均保持原实现。

后端也检查通过记录与确认参数，不仅禁用页面按钮。输入、配置、映射、凭证或图片清单变化会使旧校验失效；预检/映射重跑会清除旧 Dry Run 记录。一次正式写入会消耗 Dry Run 通过状态，重新写入需重新 Dry Run。

如果旧 run 配置设置了 target_sku/max_items，页面会提示范围受限；本版不改这些高级业务策略。确认弹窗数量按现有范围和历史成功状态计算。

## 状态和日志

workspace 仍是唯一数据来源。控制台只新增：

- workspace/<market>/03_write/console_checks.json：当前输入与配置对应的通过记录。
- workspace/<market>/03_write/logs/console_*.log / .json：任务日志和任务记录。
- workspace/.console.lock、.console_server.json：单实例启动锁与本机端口信息。

无数据库。刷新/重开浏览器保留磁盘记录；服务中断的任务显示已中断，不能按成功解锁。已有 Audit 在检测新批次前显示为“历史记录”，新批次后按当前 SKU 筛选。

最近任务日志仅显示末尾 150 行并过滤认证细节。完整日志由工作目录打开。后台异常详情保存为 console_errors.log，页面只显示可理解的提示。

## v1.1.3 操作提示

实时日志固定在右侧；窄屏置顶，可取消跟随最新日志。运行中的卡片显示等待提示与耗时。

本批次创建结果仅在实际执行创建后显示，不把历史 Audit、检测已存在或预检阻塞计为本次创建成功/失败。历史 Audit 保留原文件。重新检测完整清单开始新批次；重试 Errors 保留原批次。

预检列出具体阻塞原因。Mapping 问题出现时，打开建议 CSV、复制 AI 提示词并提供真实目标字典，人工复核后拖入 CSV，点击应用映射并重新预检。尺寸和重量问题需核实原始数据，不能通过修改映射或编造数值解决。
