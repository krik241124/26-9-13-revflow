## 尚未执行的线上验收

本轮没有使用真实账号调用保存草稿或图片上传接口。浏览器脚本使用模拟 DOM/请求验证，并非真实 Chrome 会话验收。

业务负责人需选择 5～10 个真实 SKU，包含已存在、正常待创建、Mapping 缺失、异常数据等场景，按使用说明执行：

1. 确认目标国家和店铺；切换 Market 后重新执行 ArkSwift Check / Sign in。CL 登录态可复用，国家 GUID 由配置自动选择。
2. Detect 原始完整清单，确认 errors 为空。
3. Extract；修复 ERROR/PARTIAL 后重新执行。
4. Preflight；完成必要 Mapping 并重跑预检。
5. Dry-run 全部通过后，使用 `write --sku SKU值` 逐个验收草稿。
6. 后台核对分类、颜色/材质、尺寸重量、五点描述、图片、多箱聚合和草稿状态。
7. 重跑确认成功跳过/ALREADY_EXISTS，核对 Audit/State，并执行一次实际中断续跑。

确认以上通过后再作为“生产全流程验收通过”签收，不能把离线测试当成线上成功记录。

## 保留的运行边界

- CL 国家 GUID 已进入 `config/markets.json`，RevFlow 按 market 自动选择；ArkSwift active credential 则按 market/store 强绑定，禁止跨店铺复用。
- Preflight 是正式 SOP 的人工关口，main 保持原有逐 SKU 校验/处理机制，未加新的自动审批或发布流程。
- 原有图片政策保留：扩展名、存在性、大小和数量检查，不新增图片解码校验。
- 不支持同一工作区多进程同时运行；请串行完成一个批次。更换同国家的店铺时先归档该国工作区，避免沿用旧状态。
- `.venv` 不应跨路径复制；搬迁后重新 setup。声明最低 Python 3.10，本次实际验证环境为 Python 3.14。
