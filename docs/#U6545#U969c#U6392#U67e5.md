# 故障排查

v1.1 日常入口是 start.bat。首次升级需重跑 setup.bat 安装 Flask。默认端口被占用时自动回退；ArkSwift 的 “Configured for XX” 只表示本地凭证已绑定当前店铺，点击 Check / Sign in 才会实时验证会话。Web 中旧预检/旧 Dry Run 过期时重新执行对应步骤，不能直接改通过记录。详见[控制台说明](控制台说明.md)。

| 现象 | 处理 |
|---|---|
| py/python 不存在 / setup 失败 | 安装 Python 3.10+；setup 会依次尝试 `py -3` 和 `python`。若复制了旧 `.venv` 且不可用，setup 会自动重建；同时检查公司 pip 网络访问。 |
| store_id 尚未确认 | 在 config/markets.json 填对应国家真实 ID，必须用字符串；不要复制其他国家 ID。 |
| SKU Detect API / HTTP ERROR | 检查 ArkSwift 登录与店铺权限，重新登录后对原始完整清单重跑。 |
| 商品列表结构异常 | 响应格式发生变化，结果不能当作不存在；交维护人员核对真实 API。 |
| Detect 缺文件/哈希不一致 | 在浏览器重新保存整套结果到当前市场 01_detect，不要拼接不同批次或修改 errors。 |
| RevFlow 未完成/summary 已变化 | 完整重跑 extract；中断恢复会复用缓存。不要手动修改 summary 绕过校验。 |
| CL 登录页/non-JSON/401/403 | 在控制台点击 CL → Check / Sign in 重新建立共享登录态；国家上下文由 markets.json 自动选择。 |
| ArkSwift 凭证为空/过期/401/403 | 在当前 Market 点击 ArkSwift → Check / Sign in。切换 Market 会强制作废 active credential，避免跨店铺误用。 |
| Mapping BLOCKED | 填写 review 的 suggested_target → mapping → preflight；不确定的目标交人工核对。 |
| 图片不足五张 | 查看 preflight 和图片目录；修复来源，必要时 extract --force。 |
| CL_ERROR / PARTIAL | 看 summary 的 error 和对应 SKU 原始响应；先修复提取，不能视为已存在。 |
| 没有待写 SKU | 检查 Detect、当前 summary 和已有成功状态；不要为“跑起来”随意 --force。 |
| ALREADY_EXISTS | 原有 150035 处理；在 ArkSwift 核对该 SKU，无须重复创建。 |
| 同一 SKU 内容没有刷新 | RevFlow 默认复用已完成缓存；确需刷新用 extract --force，再 preflight/dry-run。 |
| 新店铺沿用了旧状态 | 先归档该市场整个 workspace，再 init、Detect、Extract；不要跨店铺复用 state。 |

所有自动入口返回 0 表示该步骤无检测到的失败，1 表示错误或阻塞，参数错误一般为 2，Ctrl+C 为 130。部分抓取失败时会保留成功结果和报告，但需要检查非零退出码。

Preflight 是正式 SOP 的人工关口；main 仍保留原来逐 SKU 校验和继续处理其他 SKU 的行为，没有强制读取 Preflight 报告。不要跳过 SOP。

CL 国家 GUID 已由 `config/markets.json` 映射到 market；CL 登录态可以复用。ArkSwift 则按 `market + store_id` 强绑定，切换国家后必须重新 Check / Sign in。

日志、原始响应、Audit、Payload 和凭证可能包含内部业务数据。问题反馈优先提供脱敏错误文字、市场和 SKU；交付源码 ZIP 使用白名单打包工具。
