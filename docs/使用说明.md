# 使用说明

日常运营优先双击 start.bat 使用[本地控制台](控制台说明.md)，无需执行下面的命令。下文保留 CLI 技术流程。控制台新增 Python Detect 与错误重试合并；Web 的写入关口比 CLI 更严格。

## 一、配置与准备

双击根目录 `setup.bat`。后续命令在项目根目录执行。`run.bat` 固定使用项目 `.venv`；也可以用已安装依赖的 Python 调用 `launch.py`，从任意工作目录均可运行。

唯一国家入口是 `config/runtime.json` 的 `market`，支持 fr/ca/de/es/us/it/uk/pt/pl/ro。`config/markets.json` 管理各国 store_id、seller_id、country_code。店铺 ID 留空时程序会拒绝运行，不会沿用其他国家 ID。十国店铺 ID 已按业务负责人 2026-09-17 提供的清单填写；seller_id 保留原配置，并与十国历史 Payload 一致。

抓取延时、超时、图片并发等在 runtime.json。写入策略、最少图片数和草稿默认值保留在 `sku_write/config.json`；不要在该文件添加 market、arkswift、paths。默认每件最多上传 12 张、至少 5 张，保留旧图片容错和多箱聚合规则。

登录 ArkSwift，在 F12 → Network 中查看当前登录请求的 Cookie。复制 `sku_write/auth.example.json` 为 `auth.json`，填写 `raw_cookie`，或只填 `authorization_web`。凭证文件仅在本机保存。

登录 CL、切到当前国家，打开一个 SKU 的详情。在 Network 找到 GetDetail → Copy as cURL，将整段内容保存为 `revflow/getdetail.curl.txt`。切国家后必须重新获取对应国家的 cURL；工具没有十国 CL GUID 对照表，无法独立确认该 cURL 属于哪个国家。不要仅改 market 就复用另一个国家的 cURL。

运行 `.\run.bat check` 核对国家、店铺和路径。此命令只检查本地配置，不验证在线权限。

## 二、Detect

1. 原始清单存为 `workspace/<market>/00_input/skus.txt`，推荐 UTF-8、每行一个 SKU、无表头。
2. 在已登录 ArkSwift 的网页打开 F12 → Console，粘贴并执行 `sku_detect/sku_detect.js` 全部内容。
3. 面板中选择同一项目 config 目录的 `runtime.json` 和 `markets.json`，可同时选择或分别选择。面板显示来自配置的国家和 storeId，不需要编辑 JS。
4. 核对显示的目标店铺，点击选择原始 SKU 清单，等待所有查询完成。
5. 点击保存，选择 `workspace/<market>/01_detect`。必须保存完整四个文件：`<market>-all.txt`、`<market>-need_create.txt`、`<market>-errors.txt`、`<market>-detect.json`。

前三个文件分别是完整 SKU、待创建 SKU、查询失败 SKU；JSON 是市场、店铺、错误数和文件哈希记录。它最后写入，用于拒绝中途保存和混合批次。不要手工清空 errors 或修改这些文件。

有 ERROR 时停止。排查网络/登录问题后重新检测**原始完整清单**并覆盖整套结果；不要只检测错误 SKU 后覆盖 all.txt。没有待创建 SKU 时空 need_create 是合法结果；缺少 need_create 则是错误。

查询范围保留原版本的正常商品过滤 `status=1, freezeStatus=1`。其他状态的重复 SKU 仍由写入接口的 150035 结果处理为 ALREADY_EXISTS。

## 三、RevFlow

```powershell
.\run.bat extract
```

输入固定来自当前市场 01_detect，输出到 02_extract。原有 lineGuid 自动解析、GetDetail、SKU 校验、图片 SHA256 去重、图片并发和缓存续跑保留。

缺文件、errors 非空、检测市场/店铺不匹配、结果哈希不一致时，在网络请求前停止。不会回退到 skus.txt，也不会把全部 SKU 猜成 TODO。

Ctrl+C 后重新运行相同命令，复用已落盘商品和图片；不强求每个中间 CSV 行实时保存。完整运行结束才写完成标记。中断的 summary 不允许交给写入端。ERROR/PARTIAL 仍保留在 summary 供排错，返回非零退出码。

强制重新提取可用 `.\run.bat extract --force`，会刷新当前输入中需要创建的 SKU。切换 CL 国家或来源后，如需刷新历史缓存，应使用此参数。

## 四、Preflight 与 Mapping

```powershell
.\run.bat preflight
```

报告在 `workspace/<market>/03_write/review/preflight_<market>.csv`。已存在 SKU 计为 CL_SKIPPED，不作为抓取失败。BLOCKED / CL_ERROR 返回非零退出码；READY_WITH_WARNINGS 需查看图片降级、多箱聚合等原因。

出现 `mapping_review_<market>.csv` 时，不进入正式写入：

1. AI / 人工只填写 `suggested_target`、`confidence`、`review_note`，保留原始问题字段。目标须为 ArkSwift 实际分类路径或属性名称；无法确定时保留为空并交人工核对。
2. 另存为同一 review 目录下的 `mapping_review_<market>_suggested.csv`（UTF-8 CSV）。`final_target` 有值时优先于 suggested_target。
3. 执行 `.\run.bat mapping`。程序实时拉取字典；任何建议不合法则整批拒绝，不修改 Mapping。
4. 合法后先备份旧 JSON 到 `03_write/review/mapping_backups`，再更新正式 category_map / attr_aliases。
5. 再次执行 preflight，确认 Mapping 问题消失。新一轮 review 要基于新报告重新生成 suggested 文件，不要沿用旧建议。

可显式指定 `.\run.bat mapping --file workspace/fr/03_write/review/mapping_review_fr_suggested.csv`，相对路径以项目根目录为准。

`sku_write/mapping` 的三个 JSON 是业务知识库，随源码交付。建议新增映射后提交公司版本库。映射应用保持原来的实时合法性验证，不让 AI 直接调用上架 API。

## 五、Dry Run → Write → Audit

```powershell
.\run.bat dry-run
.\run.bat write
```

先确认 dry-run 所有待创建 SKU 校验通过，再执行 write。dry-run 会读取 ArkSwift 字典、校验映射/图片/完整 Payload；不上传图片、不创建或修改草稿，也不改正式 State/Audit。错误或跳过结果可记录在 review/dry_run_<market>.csv，完整日志在 logs；该 CSV 不代表完整成功清单。

正式写入保留已成功跳过、150035→ALREADY_EXISTS、Payload 快照、Audit 和原有重试逻辑。一次运行失败返回非零退出码。网络中断后可重跑；如接口已保存而本地还未记账，后续可能以 ALREADY_EXISTS 收口，需在后台核对。

单个 SKU 验收：`.\run.bat dry-run --sku SKU值`，确认后 `.\run.bat write --sku SKU值`。批量限额使用 `sku_write/config.json` 的 `run.max_items`，恢复批量前改回 null。

`write --force` 会忽略已有成功状态；若已有 skuId 且配置允许，会更新该草稿，仅在明确需要重做时使用。

输出位置：

| 记录 | 路径（相对 workspace/<market>/03_write） |
|---|---|
| 预检/映射 | review/ |
| 正式每 SKU 结果 | audit/arkswift_draft_summary_<market>.csv |
| 续跑状态 | state/results.jsonl |
| 请求 Payload | state/payloads/<SKU>.json |
| 写入和 dry-run 日志 | logs/ |

Audit 保留历史 SKU，并按当前 summary 顺序排列；同市场同 SKU 更新同一行。不要删除生产 state 后直接重跑，也不要跨国复制 state。

## 六、搬迁和备份

当前整理已完整冻结 legacy，旧模块中的运行记录归档到 archive/20260917_before_delivery；有明确市场的 State/Audit 复制到对应 workspace。无市场归属的旧 state 不自动迁移，避免复制到错误国家。旧 Detect 缺错误清单和完整性记录，不直接激活；请重新检测。

源码交付使用 tools/build_release.py，运行数据备份另行保存。新机器首次 setup 后，再受控复制所需市场 workspace 和当前凭证。更改一个市场的 store_id 表示换店铺，必须先归档该市场旧工作区，再重新 Detect/Extract；不能沿用原店铺 state。
