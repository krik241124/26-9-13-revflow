ARKSWIFT INTERNAL TOOL · 运营使用说明

ArkSwift AutoListing

Windows 本地控制台 · 版本以控制台右上角 / VERSION.txt 为准

这份说明只讲日常操作。正常使用不需要打开 PowerShell、不需要运行 Python、不需要修改 JSON，也不需要手工搬运中间文件。

日常只记住两件事：第一次使用先双击 setup.bat；以后每次双击 start.bat。浏览器打开后，严格按 Step 1 → 4 从左到右执行。

1. 启动与关闭

第一次使用

  1. 确认电脑已安装 Python 3.10+，Windows 安装时保留 Python Launcher。
  2. 在项目根目录双击 setup.bat。
  3. 看到 Setup completed 后，双击 start.bat。

以后日常使用

直接双击 start.bat。浏览器会自动打开 ArkSwift AutoListing 本地工作台。

程序默认使用 127.0.0.1:8765；端口占用时会自动换到 8766～8775。重复双击不会启动第二套任务，而是复用已有控制台。

任务运行中不要关闭启动窗口。只关闭浏览器标签页不会立即停止后台服务；抓取或写入过程中也不要同时用 CLI 跑同一批次。

2. 先选市场，再配置登录

① 选择当前市场

在页面顶部选择 FR / CA / DE / ES / US / IT / UK / PT / PL / RO。店铺 ID 已在配置中维护，普通运营不要手改。

② ArkSwift 登录

  1. 在浏览器正常登录 ArkSwift，并进入当前目标店铺。
  2. 按 F12 → Network，刷新页面，打开一个 ArkSwift 请求。
  3. 从 Request Headers 中复制 Cookie 的值，或取得 Authorization_web。
  4. 回到工具，点击 ArkSwift 登录 → 配置，粘贴并保存。
  5. 点击 测试连接。只有测试成功才说明当前会话有效。

③ CL 数据源

  1. 登录 CL，并切到与当前市场相同的国家。
  2. 打开任意一个商品详情，F12 → Network → 找到 GetDetail。
  3. 右键 Copy → Copy as cURL。
  4. 回到工具，点击 CL 数据源 → 配置，粘贴完整 cURL，保存并测试连接。
切换市场后，必须重新确认 CL 已切到对应国家，并更新对应国家的 cURL。 工具能验证请求是否可用，但无法替你判断这条 CL cURL 实际属于哪个国家。

凭证弹窗不会回显现有 Cookie / cURL，这是安全设计。“已配置”只表示本机已有内容，不代表仍未过期。

3. 四步完成一个批次

1SKU Detect
2RevFlow
3Preflight / Mapping
4Dry Run / Draft

1SKU Detect

  1. 把原始 SKU 直接粘贴到输入框，每行一个、无表头；也可以拖入 TXT / CSV。
  2. 点击 开始检测。
  3. 结果会显示：总 SKU、已存在、需要创建、查询错误。
  4. 如果有 Errors，先点击 重试 Errors；Errors 没有清零前不要进入 Step 2。

判断规则：ERROR 代表“没有查清楚”，不是“不存在”。Need Create 才是下一步需要抓取并创建的 SKU。

2RevFlow · CL Extract

  1. 确认 CL 已配置，并且国家正确。
  2. 点击 开始抓取。
  3. 程序自动读取 Step 1 的 Need Create，无需选择任何中间文件。
  4. 完成后查看“提取成功 / 异常 / 已存在或跳过”。有异常时点击 查看 Summary / 错误。

网络中断或部分失败后可以修复问题再重跑；程序会复用已完成缓存。若你明确需要刷新已抓取内容，应交由维护人员处理。

3Preflight · Mapping

  1. 点击 运行预检。
  2. 预检会检查分类、属性、图片、尺寸重量、必填字段和完整 Payload 所需数据。
  3. 若出现 Mapping 问题，按下一节处理。
  4. 若出现 BLOCKED / CL ERROR，查看报告，修复原始数据或来源问题后重新预检。
  5. 状态显示 Preflight Passed 后才能进入 Step 4。
不要为了“过预检”编造尺寸、重量、分类或属性。 Mapping 只能解决字典对应关系，不能替代事实数据核对。

4SKU Write · Audit

  1. 先点击 ① Dry Run。它会做完整校验，但不会上传图片、不会创建草稿。
  2. Dry Run Passed 后，点击 ② 创建草稿。
  3. 确认弹窗中的 Market、Store、待创建 SKU 数量。
  4. 点击 确认创建。程序开始上传图片并保存 ArkSwift Draft。
  5. 完成后查看本批次结果和 Audit，并到 ArkSwift 后台抽查草稿。

工具只创建 Draft，不自动发布商品。

4. Mapping 问题怎么处理

  1. Step 3 出现 Mapping 问题后，点击 打开 / 填写建议 CSV。
  2. 点击 复制 AI 提示词，把 CSV 与当前店铺可选类目 / 属性交给 AI 或人工核对。
  3. AI / 人工只填写建议列，不改原始问题列。
  4. 人工复核后，把填写好的 CSV 拖回页面。
  5. 点击 应用映射并重新预检。程序会用 ArkSwift 实时字典验证；非法目标会被拒绝。
字段怎么填
suggested_target建议的真实 ArkSwift 分类路径或属性名称。
confidence建议置信度，供人工判断。
review_note选择理由、证据或疑点。
final_target可选。人工最终确认值；填写后优先于 suggested_target。

无法确定就留空并说明，不要猜。新一轮 Mapping 问题使用新报告，不要直接沿用旧建议。

5. 完成后看什么

状态 / 入口含义
Draft Saved本地记录显示草稿创建成功；仍建议后台抽查。
Already Exists保存时发现 Seller SKU 已存在，按重复 SKU 规则收口，不继续重复创建。
Failed本批次创建失败，需要查看 Failed 与 Logs 排查。
查看历史 Audit完整审计记录。历史 SKU 会保留，不要手工删掉来“重新开始”。
Payload / Logs维护排查使用；运营不要手工编辑。
打开工作目录当前市场完整运行数据。不要跨国家复制 State/Audit。
推荐验收：每次批量写入后，在 ArkSwift 后台抽查标题、分类、颜色/材质、尺寸重量、图片和草稿状态，并与 Audit 对照。

6. 常见问题

现象处理
start.bat 提示先运行 setup双击 setup.bat；确认 Python 3.10+ 和 Python Launcher 已安装。
浏览器没有自动打开先看启动窗口是否显示本机地址；重复双击 start.bat 会尝试复用已有实例。
ArkSwift 401 / 403重新登录 ArkSwift，更新 Cookie / Authorization_web，再测试连接。
CL 请求失败 / 非 JSON先确认 CL 浏览器页面可用、国家正确，再重新复制 GetDetail cURL。
Detect 有 Errors修复登录或网络，重试 Errors；错误不清零不要继续。
RevFlow 有 ERROR / PARTIAL查看 Summary / Logs，修复 CL 来源或数据问题后重跑。
Mapping 无法应用目标不在当前 ArkSwift 实时字典中；重新核对真实分类 / 属性。
Preflight BLOCKED看阻塞原因。尺寸、重量、图片不足等需要修复事实数据，而不是强行映射。
“创建草稿”按钮灰色必须先 Preflight Passed，再 Dry Run Passed，并且当前仍有待创建 SKU。
改了市场 / 配置 / Mapping 后按钮又锁住正常。关键输入变化后旧校验会失效，需要重新 Preflight / Dry Run。
任务被中断重新打开控制台查看最近日志。不要删除 State/Audit；正常重跑会按已有成功状态续跑或跳过。

使用边界

  • 一个项目实例同一时间只跑一个任务，不要 Web 与 CLI 并发操作同一工作区。
  • 不要删除 State / Audit / Payload 来强制重做；确需强制刷新或换店铺，交给维护人员处理。
  • 不要把一个国家的 workspace 复制到另一个国家。
  • Cookie、Authorization、CL cURL、Payload、Logs 可能包含内部数据，不要外发。
  • 源码交付包不包含真实凭证、workspace、archive、.venv 或缓存。
